# Develop ideas and manuscripts into an explanatory video

Follow [knowledge-video.md](knowledge-video.md) as the current product contract. Favor PPT information hierarchy, legible diagrams and motion that helps explain facts. This creative reference does not authorize a video-generation service or extra approval gate.

Read this for an idea or manuscript whose visual treatment is not established,
including a fully written script with no supplied pictures. Also use it when
the user rejects a draft's overall concept as generic. Reuse an approved,
verified treatment for a focused revision.

## Separate facts from creative choices

Use the request and saved requirements to identify the subject, intended viewer
and takeaway. Distinguish supplied facts, facts needing a source, and creative
defaults. No attachment is a normal starting point, not a reason to demand an
upload or make an all-text slideshow.

- For an explainable topic, develop a focused angle and narrative. Retrieve
  relevant authoritative sources with available tools when claims need checking;
  follow [runtime-tools.md](runtime-tools.md) for actual web capabilities. Never
  describe direct URL retrieval as web search or invent a source.
- For a real product or organization with no identifying information, ask one
  compact question about what it is and whom it helps. Do not invent features,
  results, logos, testimonials or product appearance. Continue useful creative
  outlining, but do not finalize a factual promotional plan around guesses.
- For an explicitly fictional brand or story, invent its creative identity and
  keep it clearly fictional in the plan. This is not permission to invent real
  endorsements or evidence.
- Recommend reversible choices such as approximate duration, format and mood
  when unspecified. Respect existing settings. Do not turn intake into a style
  questionnaire. Only unresolved facts or choices that materially change the
  result need a question; bundle related missing facts together.

## Explore the expression before implementation

Turn the content into a visual progression. Identify the subject, the change
the viewer should witness, and the emotional or explanatory payoff. Reorganize
unlocked prose for viewing; preserve locked wording and factual meaning. Do not
assign one paragraph to each slide by default. Each shot needs a visible subject
and an action, transformation or deliberate hold that serves the film.

For example, a passage about a seed growing can become a cutaway of roots
spreading, a stem unfolding and a change of scale into the grown plant. The
illustrated subject and its change carry the idea; labels support it. This is
an example of translating meaning into pictures, not a required visual style.

When the direction is unresolved, compare a small number of materially different
approaches internally, usually two or three. Distinguish them by viewpoint,
narrative progression, visual metaphor or spatial structure, not only palette
or effect names. Select by audience comprehension, specificity to the subject,
available production capabilities and the user's intent.

For example, a process can unfold along one changing path; a comparison can
follow the same object through two conditions. These are reasoning examples,
not layouts to apply to every film. A concrete user direction takes priority.

Use [visual-direction.md](visual-direction.md) and the small
[design index](design/index.md) to load only the relevant design guidance.
Current bundled Baoyu / Frontend Slides material supports information structure
and composition. Other creative or critique skills are optional only when
actually installed and relevant; a researched name is not an available tool.
Do not install external skills during a project turn or stack entire upstream
workflows. Existing user references should yield specific keep/change decisions
about composition, color, material and motion, rather than a copied template.

Present the recommended approach and a brief reason in the existing plan. Save
the selected concept and material tradeoffs, not private deliberation or a long
brainstorm. Show alternatives when the user asks or a consequential unresolved
choice requires them. A plan must describe visible actions and transformations;
adjectives such as "premium" or "cinematic" alone are not executable direction.

## Plan where the pictures come from

Generated imagery may supply the main visual material for a text-only request.
It is not limited to small supplements. Choose deliberately per scene:

| Need | Asset strategy |
| --- | --- |
| Relationships, mechanisms, processes or sourced data | Editable text, SVG, charts or procedural animation |
| A key visual, illustration, environment or texture | Generate with an available image tool after authorization; define shared subject, palette and material first |
| Actual product, interface, person or event | Use reliable supplied/retrieved material or request the necessary source; invented visuals cannot stand in as evidence |
| Continuous character action or complex photoreal camera motion | Use supplied or reliably sourced existing footage; disclose missing material and agree on a diagram/illustration treatment when appropriate. Do not probe or call video-generation services |

In each scene's existing `assetStrategy`, identify its visual subject, source
route (supplied, generated, retrieved or procedural), shared consistency needs
and editable elements. In `visualDirection`, describe framing, depth, material
and light; in `motion`, describe subject movement, camera/framing changes and
the intended transition. A tool name or "fade in" alone does not describe a shot.
Plan new assets where they improve the approved story; do not wait for the user
to ask separately for illustration or animation. Planned assets have no
IDs until they exist. Check only the capabilities the recommendation needs;
an optional unavailable tool should not block a suitable core composition.
If a required capability is absent, explain the effect on the proposed result.
Do not silently substitute an unrelated treatment to finish faster.

## Leave one executable plan

Use `.yingya/plan.md` and the existing `scenes.json` array. Keep the creative
angle, factual boundaries, recommended direction, asset routes, sound treatment
and representative-scene choice in the existing plan sections. In each scene,
describe what the viewer first sees, what changes, and what remains to be read.
Do not invent API fields, scene states or a second brief/approval system.

Keep this stage text-only until production is authorized. The plan should make
the likely result understandable without pretending that imagined frames or
estimated timing have already been rendered or measured. Follow the normal
plan review unless the user has already authorized autonomous production.

After authorization, follow [representative-scene.md](representative-scene.md)
before committing the untested visual direction to the full film.
