# 视频分享

视频预览可播放后，点击视频下方的「分享」，创建免登录的只读播放链接，无需另行导出。分享和下载对应当前选中版本的预览文件；已有导出结果时，与播放器一样优先使用该版本的导出文件。链接公开的范围仅为固定视频、封面、标题和版本，持有链接的人可以继续转发。

- 默认有效期 7 天，可选择 30 天或长期有效；调整有效期从操作时起计算。
- 修改、重新导出项目不会改变旧分享。创建新分享会保存新的独立副本。
- 创建者可复制和取消分享；管理后台的「视频分享」支持按当前页标题、账号、项目 ID 或分享 ID 搜索并下架。管理员不获得分享凭据。
- 撤销后不能续期恢复原链接。删除项目、停用账号同步撤销；每次匿名读取还检查项目和账号状态。
- 到期后保留副本 24 小时，可在清理前调整有效期。撤销或过期的副本由网关每分钟检查，24 小时后删除。文件清理失败会重试。
- 创建失败的副本立即清理，删除成功后释放数量和存储预留；删除失败保持预留并由后台重试。旧版本遗留的“已撤销但目录已删除”记录也会自动释放预留。
- 已经下载、缓冲和正在传输的数据无法收回；没有防录屏或 DRM 承诺。

视频下方仅保留一行规格、分享与更多操作，不重复版本选择、就绪状态和解释文案。「更多视频操作 → 下载 MP4」提供备用下载入口，播放器原生下载保持可用。「导出其他规格」默认折叠，仅调整 MP4 的分辨率与帧率；点击顶部导出入口或开始后台导出时自动展开。导出历史归入该区域，主按钮使用「开始导出」，不重复表单中的规格。后台导出期间仍可分享和下载已有视频。

## 存储与播放

`<app-data>/video-shares/` 在用户 Agent 沙箱外，目录权限为 0700。SQLite 中记录分享归属、随机凭据、状态及操作记录；凭据哈希用于公开查找，原凭据只由服务器保存并向所属用户返回，以便再次复制链接。不要将此目录或数据库作为静态目录发布。

每个分享的 MP4 和 JPEG 是独立副本。创建时验证项目归属、版本或视频产物记录、路径及打开文件的实际位置；分享导出产物仍须验证已完成的导出记录，限定 MP4（H.264 / yuv420p，音轨为 AAC）。FFmpeg 只进行封装整理（faststart、移除容器元数据）和封面生成，不调用模型、不重渲染视频。视频源在复制期间发生变化会拒绝创建。

FFprobe / FFmpeg 通过 `/usr/bin/bwrap` 隔离执行，只挂载当前分享副本目录和只读系统工具，不开放宿主机用户目录或网络。输入强制使用 MOV/MP4 解复用器，禁用外部轨道引用，拒绝伪装成 `.mp4` 的播放列表。缺少隔离工具时创建失败，不回退到宿主机直接执行。

工作台仍展示最近 50 条导出任务；移出历史的已完成任务会先持久归档到项目的 `.yingya/render-completions.json`。分享同时校验当前历史和完成归档，因此旧视频不会因历史裁剪而失去分享资格。归档写入失败时保留原历史，避免丢失完成凭据。升级前已经被旧版本裁掉且没有其他完成记录的任务不会自动推定为成功。

公开媒体接口由网关直接提供，不需要创建或启动用户 worker。支持 GET、HEAD、单段 Range / 206 / 416；不接受多段 Range。页面和媒体响应设置 no-store、no-referrer、noindex、nosniff；播放页限制脚本和媒体为同源。媒体每次新请求都重新验证分享，条件请求不能绕过撤销。

生产入口 nginx 对分享页面和媒体路径脱敏，并不记录 Referer 或查询串。外层反向代理、CDN 和第三方访问日志也须按同样原则保护分享凭据；此仓库无法自动管理这些系统。

## 第一版保护上限

- 单视频最大 1 GiB，画面每边最大 8192 像素；同时最多准备 2 个分享，单个外部媒体工具最长执行 180 秒。
- 每个账号最多保留 100 条未清理的分享记录，视频存储上限 20 GB；全站视频存储上限 100 GB。准备过程还需要临时副本及封面的额外磁盘空间。
- 每账号每分钟最多 10 次创建尝试。
- 全站公开 API 每分钟最多 3000 次请求，每分享每分钟最多 600 次；每个网关进程最多 64 个媒体响应同时传输。
- 每日预留响应流量上限：每分享 20 GB、每账号 100 GB、全站 500 GB。按 UTC 日重置。
- 请求和流量计数使用 SQLite 事务持久化，滚动发布不重置。HEAD 不预留流量；完整 GET 和 Range 按各自响应长度预留，中断不退回。这是保守的保护值，不能用作实际用量计费或播放人数统计。
- 返回 429 时显示访问较多/流量保护提示。当前没有 CDN、多码率、自适应播放、精确观看统计或按访客身份的权限控制。

## 接口

- `GET /api/shares?projectId=...`：登录用户查看自己的分享。
- `POST /api/shares`：`{projectId, artifactId, days: 7|30|0}` 或 `{projectId, versionId, days: 7|30|0}`（两种来源互斥；版本来源使用记录中的 videoPath，不接收任意路径），创建完成返回链接。
- `PATCH /api/shares/{id}`：`{days: 7|30|0}`，调整有效期。
- `DELETE /api/shares/{id}`：取消自己的分享。
- `GET /api/admin/shares?offset=0`、`DELETE /api/admin/shares/{id}`：管理员列表及下架，分页 100 条。
- `GET /api/public/shares/{token}`：最小展示信息。
- `GET|HEAD /api/public/shares/{token}/video`、`.../poster`：只读成片和封面。
- `/s/{token}`：独立播放页，不经过工作台登录门槛。

## 验证与发布

Rust 的 `sharing_` 测试覆盖创建、匿名读取、跨账号隔离、跨站/账号切换拒绝、登出后观看、固定副本、Range/HEAD、续期、撤销、管理员下架、路径隔离、伪装播放列表、媒体进程的文件隔离、失败预留释放和重试、完成历史归档与重启、无效媒体、持久流量预算、项目删除和清理。导出存储测试还验证归档失败不裁掉完成记录。浏览器检查还须覆盖实际播放与拖动、分享管理、320/390 px、桌面、减少动效和发布后的真实公共地址。

使用标准不可变 release 构建/激活流程。分享数据库独立于账号和项目结构，代码回滚不需要撤销旧数据结构；旧版本不提供分享路由，因此回滚期间分享暂不可用。保留分享数据库及副本，重新启用支持分享的版本后继续按状态和有效期访问。
