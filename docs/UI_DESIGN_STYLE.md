# 映芽产品 UI 设计规范

本文档是映芽 Web 产品界面的设计依据。当前采用小鬼片场的平面漫画品牌语言，搭配 Codex / OpenAI 风格的中性工作界面：
暖白纸面、浅米灰导航与近黑主操作；借鉴 Claude 的编辑式排版与温暖中性色，山水页导航／标题采用宋体，正文和工作控件采用无衬线字体。保留映芽名称、小鬼标识、中文语气与原创素材。
Apple 的清晰层级与直接操作仍作为可用性参考。历史纸感方案见 [Kami 改造方案](KAMI_REDESIGN_PLAN.md)。

## 产品表达

产品定位遵循 [产品定位](PRODUCT_POSITIONING.md)：映芽把内容制作成可独立讲解、直接分享的视频。
起始页用文案、网页和素材作为输入引导，优先突出概念、数据和素材讲解。
说明“确认方案 → 预览与修改 → 导出成片”的工作方式；使用具体的文字、画面和节奏修改示例。
不承诺凭描述生成任意实拍镜头，也不把图片生成等素材能力说成视频生成模型。
HyperFrames 是制作底座；普通创作入口优先讲用户能完成的作品与操作。

## 设计方向

### 2026-09-21 小鬼片场

官网首页采用 2026-09-22 用户最终选定的写意水墨效果图：暖宣纸、墨色文楷「让想法」「跃然成片」两行标题、居中胶囊操作，山水集中于首屏下半部。「视频示例」与首屏共用暖宣纸纹理，山水以真实干笔边缘自然收进留白，不以直线截断，不出现独立白色矩形框。初始展示书架、花朵、海洋三张静态主题封面，16:9、同样圆角与排版；点击播放原参考视频，弹窗说明封面为主题插画。其余九个示例通过「查看更多」展开，不自动播放封面。流程区使用细分隔线与较宽留白。官网不再使用彩色手写标题和原立体小鬼片场。工作台原有山水系列与布局保留。
- 暖白主画布、浅米灰侧栏、近黑主操作。蓝色仅表示链接、焦点与实时状态。
- 官网标题与「开始创作」「观看演示」居中，小怪兽缩小后融入山水，下面衔接「视频示例」。登录后的创作起始页保留原有输入框与布局。
- 插画使用原始小鬼轮廓、黑灰线条、薄荷绿动作线和少量浅黄点缀。幽默来自姿势与眼神：举场记板、缠胶片、藏在画框后。
- 使用生成的真实图片资产，不以 CSS 或 SVG 拼画。保留原始 Logo、用户上传头像和真实客户视频封面；默认头像预设统一为原创纸拼贴小怪兽：珊瑚豆形、薄荷梨形、暖黄方形、雾蓝云朵；保留用户自传照片及已有预设选择。
- 作品、素材、账户、后台、登录、分享、介绍页与空状态统一使用 comic 素材；工作台只用紧凑标识和空状态，插画不能遮挡输入、预览、表格或按钮。
- 山水界面的品牌、主导航与页面标题按用户要求使用本地思源宋体（`--font-book`），500 字重、克制字距；正文、输入、状态、时间与模型保持无衬线字体。输入、模型和附件控件边框保持克制，键盘焦点仍清晰。
- 手机端输入工具栏保持单行；画幅设置通过“＋”菜单访问。
- 800px 以下导航采用两行：品牌、新建视频与账号在上排，我的作品／素材工坊文字标签在下排；新建按钮图文居中。
- 全站按用户要求使用中国传统山水系列背景：暖白宣纸、细墨线与淡青绿设色，少量小怪兽作为画中访客。创作／介绍页为江山行旅，作品／分享页为水乡画舫，素材工坊为竹林书斋，制作工作台为远山云海，登录／账户／后台为松庭小憩。场景主要集中于底部与边缘，上部保持留白；制作页再降低背景对比度。使用 `--story-paper` 与 `story-scenes.css` 集中管理，原始提示词和五张构建哈希素材位于 `web/src/assets/scenery/`。背景静止、不拦截交互，表格、内容卡片、菜单、表单与视频保留独立实底。
- 创作起始页按用户选定的开放书写方案：标题左侧只保留一只拿珊瑚色视频框的静态小鬼（桌面 88×72px、手机 52×48px），无横幅和入场／悬停动效。白色书写区无外框、无阴影、无灰色工具底板，底部分隔线下保留添加资料、画幅、模型与生成方案。输入与占位文字在所有宽度固定为 16px，控件统一 14px；画幅控件不使用左右竖线，以间距和悬停底色区分。输入聚焦仅加深底部分隔线。
- 原有插画资产保留归档，旧主题偏好统一迁移到 comic，不清除用户草稿。插画 URL 使用构建哈希；原图位于 output/imagegen/comic。
- 工作台保持双栏、紧凑控件与稳定输入；减少动效偏好继续生效。
- 空素材提示使用带真实 Alpha 通道的 `empty-transparent.webp`，保留小怪兽、放大镜与胶片盒；图片及空状态容器不加白底，直接透出所在页面的山水。原始白底版本保留归档。
- 制作工作台左侧对话使用竹林书斋，右侧方案／视频区保留远山云海，避免重复场景。制作方案采用有边距的暖纸面板，标题用宋体、状态单独排列；面板在可用宽度内展开，长方案在面板内滚动，空状态明确区分正在整理与等待输入。

### 2026-09-22 编辑式暖纸细化

参考 [Claude 官网](https://claude.com/) 的暖白、墨色与衬线／无衬线层级，不复用其专有字体和品牌素材。保留山水、小怪兽和开放式输入，采用 `--story-paper` #faf9f5、`--story-surface` #f0eee6、`--story-ink` #292823 与暖灰文字／边框 token；蓝色仍用于交互语义。原山水图保持静止：首页与素材轻覆 18% 纸色、作品 12%，工作台 72%，使文本更突出。标题与导航宋体改为 500 字重；描述文字保留文楷 15px，正文、输入及操作字号不变。首页内容最多 1100px，输入区最低桌面 220px／手机 200px，减少过长空白；无新卡片、动效或文案。

设计遵循以下原则：

1. **清晰第一。** 每一屏有明确焦点，标题、正文、状态与操作层级一眼可辨。
2. **内容优先。** 白色主画布承载创作内容，侧栏与检查器使用浅灰背景退居其次。
3. **直接操作。** 按钮描述结果，选中状态贴近对象，反馈及时且不打断流程。
4. **克制层次。** 优先使用留白、对齐、字号和细分隔线，浮层使用阴影，输入区不叠加装饰纸层。
5. **状态可理解。** Agent 的运行、等待、完成、中断与失败均同时使用文字和图标。
6. **输入始终可用。** 工作时仍能继续输入，并清楚选择排队或立即应用。

## 设计令牌

所有界面复用 `web/src/styles.css` 中的语义 token。历史 `--prey-*` 和
`--purple-*` 只作为兼容别名，不应在新组件中继续扩展。

| 角色 | Token | 建议值 | 用途 |
| --- | --- | --- | --- |
| 主画布 | `--canvas` | `#ffffff` | 对话、编辑与主要内容 |
| 应用背景 | `--background` | `#f7f7f8` | 导航、检查器和页面底色 |
| 抬升表面 | `--surface` | `#f7f7f8` | 控件、输入区和内容容器 |
| 悬停表面 | `--surface-hover` | `#e6e7e9` | 悬停和弱选中 |
| 主文字 | `--text` | `#202123` | 标题、正文和主操作 |
| 次文字 | `--muted` | `#55585e` | 说明和次级信息 |
| 弱文字 | `--dim` | `#6b6e75` | 元数据和占位符 |
| 分隔线 | `--line` | `#e6e7e9` | 面板边界与分组 |
| 主操作 | `--primary` | `#202123` | 创建、确认、发送 |
| 强调文字 | `--accent-text` | `#1769c2` | 灰色表面上的链接、状态文字 |
| 系统强调 | `--accent` | `#1769c2` | 焦点、链接、选中和运行状态 |
| 危险 | `--danger` | `#d70015` | 错误和破坏性操作 |
| 警告 | `--warning` | `#a05a00` | 待确认和注意事项 |

工作界面同一屏幕只使用一个强调色。蓝色表达交互或实时状态，不作为大面积背景。官网按用户选定稿使用墨色文楷标题与暖宣纸山水，少量赭橙／灰绿小怪兽不承担状态含义。

新增交互表面：`--selection`（`#eef4fb`）承载选中控件，`--selection-line`（`#bdd3ee`）标记选中边界；`--surface-inset`（`#f0f1f3`）用于预览外框与控件轨道。浅蓝仅用于交互状态，白色仍是工作画布。

## 字体与文字

- 常规控件使用 `--font-ui` 无衬线字体；山水页主导航与页面标题使用 `--font-book`（Noto Serif SC Variable），由现有本地字体包提供，不依赖外部字体服务；`--font-editorial` 保留为兼容别名。
- 中文界面使用 `--font-ui`，优先系统无衬线字体与 Noto Sans SC 回退。
- 山水界面采用「宋体标题、文楷描述、无衬线正文」：`--font-story` 使用本地分片加载的霞鹜文楷 Regular（400），仅用于首页引导语、作品／素材空状态说明、登录介绍、方案空状态首句和画面描述。说明采用 `--text-body` 15px 与正文行高，不使用细字重或人工斜体。方案章节标题延续 `--font-book` 500；对话、方案摘要、输入及占位符、按钮、状态、日期和模型仍使用 `--font-ui`。文楷不向容器或全局正文继承，字体文件随版本发布，不依赖外部 CDN。
- 等宽字体 `--font-mono` 仅用于代码、精确时间码和技术路径；模型选择、画幅选择、版本选择、状态与日期使用界面字体。数字用 `font-variant-numeric: tabular-nums` 保持对齐。

界面以紧凑、协调的工作台字号为基准。普通操作与相邻模型选择、表单标签保持接近的视觉重量；
用位置、留白、字重与按钮填色表达主次，不通过放大操作文字争夺注意力。

| 层级 | Token | 字号 | 使用范围 |
| --- | --- | --- | --- |
| 展示标题 | `--text-display` | 32–44 px | 首页主标题 |
| 页面标题 | `--text-title` | 24 px（工作台 20 px） | 素材工坊、最近作品等页面级标题 |
| 区域标题 | `--text-section` | 16 px | 工作区、抽屉、弹窗、创建音色与空状态标题 |
| 阅读正文 | `--text-body` | 15 px | 产品介绍与长文阅读 |
| 常用控件 | `--text-control` | 14 px（工作台 13 px） | 按钮、导航、模型选择、空状态说明 |
| 辅助信息 | `--text-caption` | 12 px | 表单标签、状态、说明与紧凑工具栏 |
| 表单输入 | `--text-field` | 桌面 14 px／800 px 以下 16 px | 抽屉、弹窗、音色表单与批注输入 |
| 创作输入 | `--text-creation` / `--text-input` | 桌面 17 px／移动端 16 px | 首页需求输入与移动端可编辑输入 |
| 搜索输入 | `--text-search` | 桌面 14 px／800 px 以下 16 px | 全局、项目、素材与产物搜索 |

- 必须复用语义 token；不得用浏览器默认的 16 px 充当操作按钮字号。产品按钮有 14 px 基线（工作台 13 px），紧凑控件可使用 12 px；不要继续缩小已有 12 px 辅助文字。
- 同一操作组的字号一致，包括“添加参考图”“上传素材”“生成图片”等次要入口；已有 12 px 紧凑主操作可保留。按钮主次通过填色与字重区分。
- 字重限定为正文 400、控件 500、标题/选中 600，Logo 可保持 700。抽屉与弹窗使用区域标题，不套用页面级大标题。
- 桌面表单输入与模型选择采用 14 px（工作台 13 px），标签采用 12 px。输入文字与占位符使用同字号；移动端输入使用 16 px，避免聚焦时页面缩放。
- 缩小字号不等于缩小点击区域：保留现有控件高度、内边距与焦点环，新增触摸操作至少提供 40 px 高度；小图标关闭按钮可保留现有 32–36 px 点击区域。
- 制作页对话与输入继续使用 13 px 紧凑布局；营销展示和客户视频中的文字按各自内容设计，不套用工作台控件字号。
- 中文阅读正文行高 1.8，控件与说明行高 1.5-1.65。中文工作区标题不压缩字距；仅首页展示型标题允许 -0.02em。
- 文案简洁、具体，优先“动作 + 对象”，例如 `生成脚本`、`确认并制作`。
- 不喊口号，不写泛化励志语，不重复解释显而易见的操作。只保留内容、操作和必要状态。
- 不使用装饰性大写标签、拟人闲聊、虚假精度和无解释的英文。

## 形状、边界与阴影

- 山水页面复用 `--story-paper`、`--story-surface`、`--story-line` 与 `--story-panel`：导航、表单、菜单使用暖白纸色，内容面板使用 98% 不透明纸色。作品与素材卡片采用完整圆角纸面，封面、标题与元数据形成一个整体，不在标题下保留独立纯白矩形；表格与统计区域仍有足够实底保证可读。
- 8 px：紧凑图标容器。
- 12 px：按钮、输入、标签和列表行。
- 18 px：主要输入区、预览和检查点。
- 全圆胶囊仅用于确实需要的短状态或分段控件。
- 相邻面板用 1 px 系统灰分隔线区分。
- 普通内容不使用悬浮卡片阴影。阴影用于菜单、模态框和固定输入浮层；首页输入区保持单层边框。
- 按钮按下可下移 1 px 或缩放至 0.98；不使用发光、弹跳或大范围旋转。

## 产品布局

### 桌面工作区

- 统一左侧对话、右侧方案／视频，顶栏展示作品名、状态、版本相关操作和分享下载。没有视频编辑器或新旧视图切换。
- 1024 px 起双栏，对话默认约三分之一，320–560 px 可调，预览至少 480 px；支持拖动、键盘、双击恢复及本机保存。
- 不足 1024 px 使用对话、方案、视频标签；制作详情在次级入口打开。输入、当前任务和反馈入口始终容易找到。
- 视频保持原始比例；制作中继续看已有视频，不能以空白工程加载屏替代。
- 方案展示目标、讲解大纲、实际内容关键画面和素材说明，通过自然语言修改，单一主动作“按这个方案制作”。
- 技术日志、工程文件和检查报告收进制作详情。普通用户不需要看文件路径或操作专业控件。
- 修改通过截图圈选、时间点／时间范围加文字；反馈绑定版本，多条可一起发送。失败保留旧结果和反馈。

### 起始页

起始页按上方漫画规范，保留短导航、简短标题与说明、三幕插画、创作输入区；内容组靠上排列，输入区下方不重复展示流程文字。作品列表在「我的作品」中显示，
使用真实视频封面与名称、状态、更新时间，方便继续创作。
项目分为制作中、待处理、可导出、已导出、待恢复。已有视频不要求对话确认；已导出依据当前视频版本的导出记录，源文件有更新时单独提示。

### 窄屏与移动端

小于 1024 px 时，工作区通过对话、方案和视频标签切换；小于 800 px 时全局导航收敛为顶部工具栏。对话输入区
保持可见，预览页提供直接描述修改的入口，不能遮挡内容。最低支持 320 px，并重点检查 390 px。

## 组件行为

### 项目导航

- 默认列表透明，悬停使用更深一级系统灰。
- 选中项使用白色表面、1 px 边框和轻微阴影，不使用彩色背景。
- 运行中项目同时使用蓝色状态点和文字标签。
- `新建视频` 是左栏唯一占主导的深色实心按钮。
- 删除操作在悬停、键盘聚焦和触摸场景中均可发现。

### 输入区

- 全站表单统一使用中性灰原边框表达输入焦点，覆盖登录、后台、搜索、素材、分享与弹窗；不增加外侧焦点环或蓝色阴影。

- 使用白色表面、1 px 边框和 18 px 圆角。
- 创作输入区使用白色表面与浅灰细边框，聚焦时仅加深为中性灰边框，不显示蓝色外圈、不上浮、不发光；内部按钮保留键盘焦点环。
- 描述草稿静默自动保存，不显示保存成功提示；保存失败时保留明确提醒。
- 附件和上下文以可移除标签进入输入流。
- 上传、模型、音色、画幅、排队、停止和发送保持稳定位置。
- 工作区输入框底部保持单行，仅展示「＋」、模型与发送；运行时停止按钮与发送相邻。上传素材、选择素材、旁白音色收进「＋」菜单，菜单项统一使用图标加文字，并展示当前音色。窄屏优先截断长模型名，不拆行或挤走发送按钮。
- 正在运行时，新消息默认排队；发送后可在排队消息上点击“立即执行”，中断当前任务并优先处理该条消息。停止按钮与发送按钮相邻，保留独立操作。

## 动效

动效强度保持低到中等，仅用于状态变化和直接反馈：

- 焦点、悬停、按下、选择和展开使用同一组时长 token；状态与输入立即更新，动效只承接视觉变化。
- 保留既有布局，以“快响应、缓收尾”统一操作手感。快速反馈 160 ms，标准切换 240 ms，面板进入 360 ms；进入使用减速曲线，退出使用加速曲线。
- 筛选与标签的选中标记在原位滑动；快速连续操作从当前画面接续，调整窗口后重新对齐。
- 作品出现依次延迟 28 ms，最多累计 140 ms；封面悬停轻微放大，操作提示淡入，键盘聚焦也能发现入口。触摸设备不依赖悬停。
- 模态框短距离淡入，关闭时快速收起；任务面板与菜单共用可中断开合，动画不延迟状态更新与输入。
- 新视频载入时短暂淡入；不因装饰动效重新加载视频、自动播放或改变播放位置。
- 允许 4-8 px 短距离淡入、面板滑入、按钮按下和运行状态脉冲。
- 禁止持续环境动画、装饰性漂浮、发光扫描、旋转按钮和大幅弹跳。
- `prefers-reduced-motion: reduce` 下关闭非必要动画与平滑滚动。

## 无障碍与质量门槛

- 所有控件支持键盘。文本输入、多行输入、搜索框和原生下拉框聚焦时仅将原边框加深为中性灰，不显示外圈、蓝框或发光；无边框内层输入由外层容器呈现焦点。按钮、链接等其他控件保留清晰的 2 px 键盘焦点环。
- 纯图标按钮具有中文无障碍名称和适当的 `title`。
- 文字与图标达到 WCAG AA；占位符和弱文字也需保持可读。
- 状态至少使用文字、图标、形状中的两种，不只依赖颜色。
- 中文、长路径、长项目名与模型名必须有明确的截断或换行策略。
- 短按钮和折叠状态的下拉选项保持单行；宽度需同时容纳最长常用选项、图标、箭头、间距和内边距，不能只验证默认选项。长名称截断时仍需能在展开列表中读全。
- 响应式表单改为单列后，输入与下拉同步占满列宽，不得残留桌面的 50% 宽度；主操作保持至少 40 px 点击高度。手机端固定数量的素材分类全部可见。
- 测试桌面双栏、面板调整、390 px、320 px 和减少动效模式。
- 检查抽屉、空状态、表单与弹窗的字号是否一致；确认按钮未继承为 16 px、手机输入为 16 px、点击区域与键盘焦点未随字号缩小。
- 前端改动后运行 `npm run typecheck`、`npm run web:build`、相关 UI 测试，
  并按照本文规范进行桌面与移动端截图检查。
