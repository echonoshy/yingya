# 映芽产品 UI 设计规范

本文档是映芽产品界面的设计依据。设计参考 Kiro 的专注感、直接性、可见的
Agent 活动与结构化进度，并将这些特征转化为适合中文 AI 视频制作工作台的
界面语言。

参考样本于 2026-09-01 从 Kiro 官网、官方文档和当时的产品截图中整理。Kiro
只作为方向参考，不是映芽品牌素材、文案或页面模板的来源。

## 设计方向

映芽应当像一张安静而可靠的制作台：暗色、精确、响应及时，同时保留少量温度
与生长感。界面本身退后，让对话、制作状态和视频产物成为视觉中心。

设计遵循五条原则：

1. **工作内容是主角。** 内容和任务状态拥有最强层级，应用框架保持克制。
2. **Agent 的工作可理解。** 读取、规划、执行工具、等待确认、完成、中断和
   失败必须是可区分的状态。
3. **输入始终在手边。** Agent 工作时仍可输入；排队发送和立即打断必须是明确
   的选择。
4. **复杂度原地展开。** 默认先展示摘要，工具输出、源码、调试事件、设置和次要
   操作只在需要时展开或覆盖显示。
5. **平静优先于炫技。** 先用表面层级、字体和间距解决问题，再考虑辉光、渐变、
   阴影或动画。

## 视觉语言

### 色彩系统

产品采用暗色优先。近黑表面带有很轻的紫色相，在不变灰、不偏蓝的前提下建立
深度。实现时直接使用 `web/src/styles.css` 中已有的 token。

| 角色 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 画布 | `--black` | `#000000` | 应用背景和中央工作区 |
| 深凹面 | `--prey-950` | `#0d0b0f` | 日志、源码、深层容器 |
| 表面 1 | `--prey-900` | `#19161d` | 输入框、列表行、默认卡片 |
| 表面 2 | `--prey-800` | `#211d25` | 选中或抬升的控件 |
| 表面 3 | `--prey-750` | `#28242e` | 按钮和紧凑控件 |
| 分隔线 | `--prey-700` / `--line` | `#352f3d` | 分隔和安静边界 |
| 强边界 | `--prey-600` | `#4a464f` | 输入框和交互轮廓 |
| 主强调 | `--purple-500` | `#9147ff` | 主操作和当前状态 |
| 悬停强调 | `--purple-400` | `#a96fff` | 聚焦或悬停的紫色控件 |
| 柔和强调 | `--purple-300` | `#c59eff` | 图标、链接、激活标签 |
| 主文字 | `--text` | `#fafafa` | 标题和重要内容 |
| 次文字 | `--muted` | `#c1bec6` | 正文和次级标签 |
| 弱文字 | `--dim` | `#928d9a` | 元数据和占位符 |
| 危险 | `--danger` | `#ff716c` | 错误和破坏性操作 |
| 警告 | `--warning` | `#f7be5b` | 待检查和警告状态 |

普通工作区视口可按约 75% 黑色/深凹面、20% 分层表面与文字、最多 5% 强调色
来控制视觉重量。紫色必须表达明确意图：主操作、键盘焦点、选中、激活导航、
Agent 当前工作或链接。不要用大面积紫色承载普通内容。

映芽的绿色 Logo 是品牌识别点，不应改成紫色，也不要把 Logo 渐变扩散到产品
控件。品牌绿仅用于 Logo 和极少数“创作成功/萌发”时刻；常规成功状态仍需同时
提供图标和文字。

### 字体

- 产品界面和中文文案使用 `--font-ui`：当前为 Noto Sans SC Variable 及中文
  系统字体回退。
- 技术元数据使用 `--font-mono`：当前为 Fragment Mono 及系统等宽字体回退。
- 不导入或分发 Kiro/AWS 的专有字体。
- 段落、按钮、对话和长文本使用无衬线字体；小型分区标签、模型名、文件路径、
  时间、计数、画幅和代码使用等宽字体。
- 默认使用正常句式。全大写英文只用于 `VIDEO PROJECT`、
  `REVIEW CHECKPOINT` 这类短眉题。
- 建议字号：元数据 11–12 px，控件/正文 13–15 px，工作区标题 18 px，空状态
  标题 28 px；48–68 px 只用于起始页主标题。
- 正文行高控制在 1.55–1.8。负字距只用于大标题，中文正文不使用紧缩字距。

### 形状、边界和层级

轮廓要柔和，但不能处处圆润得像气泡。

- 8 px：极小图标按钮和紧凑内部元素。
- `--radius-control` / 12 px：输入、标签、列表行和次级按钮。
- `--radius-button` / 16 px：主按钮、输入区和组合控件。
- `--radius-panel` / 24 px：覆盖层和主要面板。
- 全圆角胶囊：仅用于状态点、滚动条或真正的胶囊形元数据；避免所有控件都变成
  药丸形。

多数表面使用 1 px 边界。相邻面板使用分隔线或色阶区分，而不是阴影。阴影只
用于菜单、模态框和浮层，保持宽、暗、低透明度。辉光只属于正在创作的预览或
Agent 运行状态，并且不能降低文字对比度。

### 间距与密度

使用 4 px 基础网格，常用序列为 4、8、12、16、24、32、48、64 px。控件保持
紧凑，主要内容列保留足够呼吸空间。

- 紧凑图标/控件间距：6–8 px。
- 控件内边距：10–14 px。
- 卡片/面板内边距：16–24 px。
- 大分区间距：24–40 px。
- 最小指针目标：38 × 38 px；主操作优先 42–48 px。
- 避免“有边框的卡片嵌套有边框的卡片”；新增一层边界前先尝试移除一层。

## 产品布局

### 桌面工作区

默认结构是稳定的三分区制作工作台：

```text
┌──────────────────┬──────────────────────────────┬──────────────────────┐
│ 项目列表         │ 对话 / Agent 工作            │ 产物 / 预览          │
│ 232–276 px       │ 最小 440 px，占剩余空间       │ 约 440 px，可调整     │
│ 常驻             │ 底部输入区常驻                │ 按上下文出现          │
└──────────────────┴──────────────────────────────┴──────────────────────┘
```

- 顶栏高度使用 72 px，承载项目身份、状态和高价值操作。
- 左栏是导航，不是数据看板。展示项目名、简短状态和时间；删除等破坏性操作仅在
  悬停或聚焦时出现。
- 中央列承载对话、统一的 Agent 活动、检查点、消息队列和输入区。
- 当产物或预览重要时打开右侧画布，但不能因此让输入区消失。
- 调整器需要有明确的悬停/聚焦反馈，并持久化用户调整后的宽度。

### 起始页

使用一句有力主张、一段辅助说明、一个大型输入区和一小排起始建议。环境网格、
光球和 Agent 小标签可以营造氛围，但必须低对比且不可交互。起始页不是营销落地
页，不放功能卡片墙、用户证言和装饰性导航。

### 窄屏与移动端

无法同时容纳多列时，用明确的 `对话 / 产物 / 预览` 标签切换。访问项目和输入区
不能依赖横向滚动。吸顶栏不得遮住聚焦输入框、确认请求或对话最后一项。320 px
作为硬性最小宽度，同时测试常见的 390 px 手机宽度。

## 组件行为

### 项目导航

- 默认列表行透明，悬停后升为表面 1。
- 选中行使用表面 2、安静边框和 3 px 紫色左侧指示条。
- 运行中项目同时使用文字标签、动效和小型强调标识，不能只靠紫色文字表达。
- `新建视频` 是左栏唯一的实心紫色控件。

### 输入区

输入区是产品中最重要的控件。

- 使用表面 1、1 px 强边界、16 px 圆角和无单独边框的 textarea。
- 聚焦时加强紫色边界，最多上移 2 px。
- 附件和上下文以可移除标签的形式进入输入流。
- 上传、模型、画幅、排队/立即应用、停止和发送在底部工具栏保持稳定位置。
- 发送按钮是紧凑的实心紫色方形；禁用时同时降低对比度并禁止指针行为。
- Agent 工作时用户仍能写下一条指令，并清楚看到它会“排队”还是“立即应用”。

### Agent 活动与状态

工作过程呈现为一条按时间排序的统一流。先给出运行摘要，再在下方用可展开行
承载命令、工具输出和技术详情。

- 运行中：旋转/脉冲标识 + 现在进行时动作。
- 已完成：勾选图标 + 简短的完成摘要。
- 等待用户：抬升的检查点/请求卡片 + 明确操作。
- 失败：危险图标、通俗的失败原因；如果存在恢复路径则提供操作。
- 已中断：中性图标 + 明确的 `已中断`，不能伪装成成功。

不要形成一堵逐条加框的工具卡片墙。已完成的后台操作应合并展示，命令和输出
按需展开。当前正在做的事情必须和历史记录明显区分。

### 检查点与授权

检查点是用户重新获得控制权的时刻，不是庆祝横幅。使用一个强调边框、说明性
标题、简短的结果导向文案、可用时提供预览，以及一个主决定。警告/授权请求用
琥珀色，破坏性确认用红色。按钮应描述结果，例如 `确认并制作`，不要只写
`确定`。

### 产物画布

- 面板使用最深表面，控件使用普通表面。
- 标签页区分产物浏览和渲染预览。
- 预览框可使用克制的紫色边缘/渐变来标记创作输出区域；源码和 Markdown 视图
  保持中性。
- 文件标签、路径、版本和待检查状态无需打开调试信息即可看到。
- 不要给用户生成的视频内容覆盖应用的紫色色调。

### 按钮、图标和菜单

- 主按钮：实心紫色、白字；每个局部决策区最多一个占主导的主操作。
- 次按钮：表面 2/3 + 边框；悬停只上升一个色阶。
- 三级按钮：默认透明，悬停/聚焦时出现表面。
- 破坏性按钮：作为附属操作时默认中性，表达意图时变红；红色实心只用于最终
  破坏性决定。
- 使用 `@phosphor-icons/react`，同一控件组内保持一致图标粗细。常规图标为
  16–20 px，不使用 emoji 充当界面图标。
- 菜单和上下文浮层锚定触发控件，在当前任务附近打开并支持 Escape 关闭。模型、
  上下文、用量或设置选择优先使用浮层，不要跳离工作区。

## 动效

动效用于解释状态变化，而不是装饰静止界面。

| Token | 时长 | 用途 |
| --- | --- | --- |
| `--motion-quick` | 140 ms | 按压、图标、悬停反馈 |
| `--motion-standard` | 260 ms | 聚焦、菜单、表面切换 |
| `--motion-slow` | 520 ms | 面板和场景进入 |
| `--ease-sprout` | `cubic-bezier(.16, 1, .3, 1)` | 默认减速曲线 |
| `--ease-play` | `cubic-bezier(.175, .885, .32, 1.275)` | 极少数俏皮品牌时刻 |

允许的模式包括短距离显现/淡入、2 px 抬升、细微运行脉冲、面板滑入和首次进入
时的主标题字符错落。持续动画仅用于进行中状态和非常淡的起始页氛围。避免视差、
跟随光标、巨大弹跳、普通卡片上的永久渐变，以及不相关区域同时运动。

在 `prefers-reduced-motion: reduce` 下移除持续氛围、字符错落、旋转、弹跳和大幅
位移，保留即时状态变化和焦点反馈。

## 文案风格

使用简洁的简体中文和冷静的制作语气。

- 优先使用“动作 + 对象”：`生成分镜`、`查看计划`、`停止渲染`。
- 在确认、停止、替换或删除时说明操作后果。
- 只有在识别具体工作者或能力时使用 `Agent`，其他场景用用户能理解的工作语言。
- 状态标签保持简短统一：`准备中`、`制作中`、`等待确认`、`已完成`、
  `已中断`、`失败`。
- 避免夸张宣传、拟人闲聊、虚假精度和无解释的英文。路径、模型名、格式和已建立
  的产品术语可以保留英文。

## 无障碍与质量门槛

所有面向用户的改动必须满足：

- 所有控件可通过键盘访问，并显示 2 px 可见焦点环。
- 纯图标控件具有中文无障碍名称；适合时同时提供可见 tooltip/title。
- 文字和有意义图标达到 WCAG AA 对比度；弱文字放在深凹面上时必须实测。
- 状态至少同时使用文字、图标、形状、动效中的两种，不能仅靠颜色。
- 只在悬停出现的操作也应在键盘聚焦时出现，并在触摸设备上保持可发现。
- 加载过程保持布局稳定；空、错误、中断、离线和超长内容状态需要明确设计。
- 中文、长路径、长项目名和模型名需要有意地截断或换行。
- 测试桌面多面板、面板调整、320/390 px 宽度、页面缩放和减少动效模式。
- 前端改动后运行 `npm run typecheck`、`npm run web:build` 和相关 UI 测试。

## 禁止模式

不要引入：

- 通用 SaaS 数据看板式卡片网格；
- 覆盖主要工作表面的玻璃拟态；
- 每个激活或悬停对象都有霓虹紫色辉光；
- 普通按钮或文字的渐变填充；
- 过量药丸、巨大圆角容器或层层嵌套的卡片；
- Agent 工作时隐藏输入区；
- 原始工具日志和 Agent 的自然语言状态争夺视觉层级；
- emoji 图标、混用图标库或 Kiro 的幽灵标志、字标和插画；
- 复制 Kiro 产品文案、品牌资产或像素级复刻页面。

## 评审清单

接受视觉改动前，对每个相关问题都应回答“是”：

- 当前项目、Agent 当前状态和用户下一步是否一眼可见？
- 输入区是否容易找到，并且在工作进行时仍可使用？
- 是否复用了现有 token，并只在有意义的位置使用紫色？
- 次要复杂度是否按需展开？
- 每个决策区是否只有一个占主导的操作？
- 间距和表面层级是否比阴影和特效承担了更多工作？
- 悬停、聚焦、触摸、加载、空、错误和减少动效状态是否覆盖？
- 最终结果是否仍然像映芽，而不是 Kiro 的复制品？
