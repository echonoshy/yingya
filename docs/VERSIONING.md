# 开发版本与更新说明

映芽使用 `主版本.中版本.修订号`，从 `0.1.0` 开始。`versions.json` 按新到旧保存每个开发版本，第一条就是当前产品版本；`package.json` 与 `package-lock.json` 保持一致。早于此记录的历史部署不补造版本号。

- 修订版本（如 `0.1.1`）：修复和小调整，记录开发变更即可。网页显示最新版本号，但不新增更新说明。
- 中版本（如 `0.2.0`）：有一组值得向用户说明的功能变化，填写简短标题与摘要，网页展示一条更新。
- 主版本（如 `1.0.0`）：产品进入新阶段。低位归零，同样填写一条网页更新说明。

网页入口为登录后的「账号 → 版本记录」，只显示中版本起点（修订号为零）的标题和摘要，不自动弹窗。开发明细留在仓库。

## 记录下一版

在完成一批开发工作后、发布前执行；不是每个 Git 提交都递增版本：

```bash
npm run version:record -- patch --change "修复视频预览跳转"

npm run version:record -- minor \
  --title "更方便地整理素材" \
  --summary "新增素材文件夹和搜索，找回需要的图片、音频与视频更方便。" \
  --change "增加文件夹管理" \
  --change "增加素材搜索"
```

每次选择其中一条命令。`--change` 可重复传入；日期默认取上海当天，可用 `--date YYYY-MM-DD` 明确指定。命令先校验所有记录，再同步三个版本文件；不会自动提交、打 Git 标签、推送或部署。

网页摘要面向使用者，控制为一两句话，说明实际变化；不要把内部命令、模型配置或部署细节写进摘要。开发变更可保留具体工程信息。

运行 `npm run version:check` 校验三段式版本、日期、顺序、摘要与包版本一致性。`npm run web:build` 和 `release:build` 都会执行校验，错误时阻止构建。

## 产品版本与部署编号

`0.1.0` 是产品版本；`20260929-...` 是不可变部署编号。同一产品版本可以重新构建和部署，日期编号继续用于切换、定位日志与回滚。

发布快照同时包含版本记录，`release.json` 和 `data/deployment/active.json` 的 `appVersion` 记录产品版本。回滚时网页和版本说明一起回到对应快照。回滚到尚未引入版本记录的旧快照时，没有 `appVersion` 字段。

Rust 的 `Cargo.toml` 版本是内部服务包版本，不参与产品版本递增。版本工具不改动项目或账户数据。
