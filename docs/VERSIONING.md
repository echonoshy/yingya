# 开发版本与更新说明

映芽使用 `主版本.中版本.修订号`，从 `0.1.0` 开始。`versions.json` 按新到旧保存每个开发版本，第一条就是当前产品版本；`package.json` 与 `package-lock.json` 保持一致。早于此记录的历史部署不补造版本号。

- 修订版本（如 `0.5.55`）：快速迭代的默认选择，每版记录一句简要变化。
- 中版本（如 `0.6.0`）和主版本（如 `1.0.0`）：仅用于成组功能或阶段变化，记录开发变更即可，不需要另写标题和摘要。

网页入口为登录后的「头像 → 帮助 → 版本记录」，按新到旧显示最近 5 个修订版本（修订号非零）的版本号、日期和简要变更，不展示 `0.x.0` 介绍，不自动弹窗。完整历史留在仓库。

## 记录下一版

在完成一批开发工作后、发布前执行；不是每个 Git 提交都递增版本：

```bash
npm run version:record -- patch --change "新增文档预览，优化素材整理。"
```

`--change` 直接用于网页说明，每版优先写一句重要变化；少量并列变化可重复传入。不要罗列内部命令、模型配置或部署细节。日期默认取上海当天，可用 `--date YYYY-MM-DD` 明确指定。

命令先校验所有记录，再同步三个版本文件；不会自动提交、打 Git 标签、推送或部署。旧记录中的标题和摘要仅作历史存档，不再用于网页展示。

运行 `npm run version:check` 校验三段式版本、日期、顺序、变更与包版本一致性。`npm run web:build` 和 `release:build` 都会执行校验，错误时阻止构建。

## 产品版本与部署编号

`0.1.0` 是产品版本；`20260929-...` 是不可变部署编号。同一产品版本可以重新构建和部署，日期编号继续用于切换、定位日志与回滚。

发布快照同时包含版本记录，`release.json` 和 `data/deployment/active.json` 的 `appVersion` 记录产品版本。回滚时网页和版本说明一起回到对应快照。回滚到尚未引入版本记录的旧快照时，没有 `appVersion` 字段。

Rust 的 `Cargo.toml` 版本是内部服务包版本，不参与产品版本递增。版本工具不改动项目或账户数据。
