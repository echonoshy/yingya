# 映芽 Kami 纸感改造方案

日期：2026-09-21。状态：UI 已实施、验收并发布；本轮未改后台逻辑。

## 目标与依据

统一成「Kami 纸感 + 映芽小鬼」：暖纸底色、墨蓝交互、书刊式标题，配合有情节的纸面插画。
创作入口与外围页面更有趣、更有层次；正式制作工作台保持高信息密度。

本轮明确要求：保留映芽 icon 宠物；增加图案装饰；九套界面风格收敛为纸相关方向；全部原有素材保留；
按 Kami 规划；根据页面任务区分密度。

本轮补充范围：**仅修改前端 UI，后台实际生成效果不作为本版验收条件。**

### 本版边界

- 修改页面排版、设计令牌、插画呈现、组件样式、响应式及前端交互反馈。
- 沿用现有路由、API 契约、业务动作与数据结构；不改 Rust、数据库、模型、视频生成、计费与任务调度逻辑。
- 可以使用隔离的浏览器 API mock 展示运行中、成功、失败等界面状态，无需启动真实视频任务。
- 输入、菜单、筛选、标签切换、面板调整、弹窗、焦点及媒体控件仍须可操作；不把页面做成只可观看的截图。
- 模拟数据仅用于测试与预览，不替换正式站 API，也不在正式产品中展示虚构作品、进度或账单。
- 本轮已进入实施；UI 按仓库流程发布并验证公网前端。前端发布可能涉及已有 release 网关切换，
  这不扩大为后台功能开发或生成质量验收。

参考：

- [Kami 仓库](https://github.com/tw93/Kami) 与已安装的 `kami/references/design.md`。
- 当前 `docs/UI_DESIGN_STYLE.md`、`docs/STUDIO_THEMES.md`、主题实现及原始素材。
- 本方案基于源码、纸张原稿、铅笔插画及仓库现有的首页／工作台／素材工坊截图；
  已生成并按“文案克制”的反馈修改三页概念图。仓库存量截图不代表已重新验证当前线上版本。

Kami 主要是文档与落地页的排版系统。这里使用其视觉语言，应用布局、控件与任务反馈仍按映芽工作流设计。
本轮用户要求优先于旧规范中的冷灰配色、九主题随机切换及仅一张独立首页插画限制。
已同步修订旧规范；保留其中的可用性、响应式、状态反馈和发布要求。

## 1. 品牌与视觉基线

### 品牌

- 保留 `web/public/brand/yingya-ghost.png`、favicon 和官网 `BrandLogo.tsx` 的小鬼轮廓与识别特征。
- 小鬼继续担任品牌主角；不同页面让它与纸框、分镜、文件夹、手账互动。
- 官网保留现有点击彩蛋；创作入口可有一次短反馈，工作台中的小鬼静止。
- 控件继续使用 Phosphor 图标。装饰图不承担操作或状态的唯一表达。

### 配色与字体

以下是拟议映射，统一修改 `web/src/styles.css` 的语义令牌，避免页面各自覆盖色值。

| 角色 | 拟议方向 | 使用边界 |
| --- | --- | --- |
| 外围背景 `--background` | Kami 暖纸色 `#f5f4ed` | 官网、登录、创作入口和应用外框 |
| 常规表面 `--surface` | 象牙白 `#faf9f5` | 纸面容器与次级区域 |
| 内容画布 `--canvas` | 白色或接近白色 | 高密度对话、表单、内容和媒体区域，按实测对比确定 |
| 边界 `--line` | 暖灰 `#e8e6dc` | 分组分隔；输入轮廓与焦点另验对比度 |
| 正文 `--text` | 暖近黑 `#141413` | 紧凑正文与标题 |
| 主操作与强调 | 墨蓝 `#1B365D` | 主按钮、链接、选择与焦点，控制面积 |
| 失败与警告 | 保留可区分的语义色 | 不因统一墨蓝而丢失状态区别，配文字与图标 |

- 官网、登录和创作入口的展示标题使用已有 Noto Serif SC；辅助说明按阅读需求排版。
- 导航、按钮、表格、对话、搜索、输入继续使用现有无衬线 UI 字体。
- 桌面常用控件和工作区对话维持 13px，辅助信息不低于 12px，移动端输入保持 16px。
- 不引入 Kami 默认中文字体：仓库已有 Noto Serif SC，可直接承担纸面标题角色。
- 沿用语义圆角、间距和动效 token；纸感主要来自配色、排版、插画和少量纸层，不把所有控件做成拟物纸片。

### Kami 规则如何映射到映芽

| 维度 | Kami 参考 | 映芽落实方式 |
| --- | --- | --- |
| 字体 | 衬线字体表达书刊气质，400／500 字重形成层级 | 展示标题使用 Noto Serif SC 400／500；工具界面使用现有无衬线 400／500／600 |
| 配色 | 暖纸、暖灰、墨蓝 | 全站语义 token 统一暖色中性表面，墨蓝承担交互；插画保留自身的低饱和色 |
| 排版 | 对齐、字级、段落节奏建立层级 | 保持映芽的导航与分栏，通过间距和细分隔区分区域，避免层层套卡片 |
| 表面 | 平面为主，阴影用于真正浮层 | 列表、表格不加投影；仅首页输入区允许轻微纸层，菜单与弹窗沿用浮层阴影 |
| 图案 | 克制的插画与几何图示 | 优先现有纸张小鬼、画框、文件夹与铅笔画；增加局部构图，不增加装饰性文字 |
| 密度 | 按阅读用途调整行高和内容宽度 | 外围页面舒展，正式工作台保持紧凑字号、固定输入和充足预览面积 |

这里明确采用两类字体，是针对应用控件的适配；不照搬 Kami 文档的通篇衬线字体、印刷单位和固定页幅。
也不将旧规范的冷灰、系统蓝和新墨蓝混用为两套视觉主题。

### 字体与间距实施规格

新增展示字体语义 token `--font-editorial`，建议字体栈：
`"Noto Serif SC Variable", "Noto Serif SC", "Songti SC", "STSong", serif`。
已在产品入口导入现有 Noto Serif SC 依赖，并验证素材页标题的字体加载。
旧官网 `Yingya WenKai` 是固定标题字形子集，不能拿来渲染任意新标题；保留该资源，标题逐步统一至展示字体 token。

| 文本角色 | 字体与字重 | 字号与行高 |
| --- | --- | --- |
| 官网必要的展示标题 | 衬线 500 | 32–40px，1.2–1.3 |
| 首页／登录的简短标题（确有必要时） | 衬线 500 | 24–32px，1.3 |
| 作品／素材页面标题 | 衬线 500 | 20px，1.3 |
| 工作区、抽屉、弹窗标题 | 无衬线 600 | 16px，1.5 |
| 导航、控件、对话、桌面输入 | 无衬线 400／500 | 13px，1.5–1.6 |
| 标签、元数据 | 无衬线 400／500 | 12px，1.5 |
| 首页输入／手机可编辑输入 | 无衬线 400 | 16px，1.6 |

长正文沿用阅读行高，不把密集控件行高套到方案长文。数字使用等宽数字特性，普通控件不改成等宽字体。
中文正文和控件不额外拉大字距；不使用斜体、全大写英文角标和粗重装饰标题。

间距按 4px 基数统一：控件内部 4／8px，紧凑分组 12／16px，内容区内边距 16／24px，
外围页面分区 32／48px。正式工作台不套用外围页面的大间距。
沿用现有 12px 控件、14px 按钮、18px 面板圆角 token；纸张装饰可以自然不规则，真实可点击区域保持规则。
移动端触摸操作至少 40px，图标关闭按钮沿用已定义的 32–36px 区域；字号变紧凑不缩小点击范围。

### 文案克制（概念图反馈）

- 趣味通过小鬼、插画、纸面构图表达，不靠口号、鸡汤或拟人闲聊。
- 禁止“灵感不设限”“把日常变成好故事”“好的创意从素材开始”等装饰性口号。
- 导航、按钮、标题使用直接名称，例如“新建视频”“素材工坊”“生成方案”；说明仅在帮助操作时出现。
- 首页不强制增加宣传大标题；输入提示可直接使用“描述视频内容，或添加参考资料”。
- 纸条、便签、图章等装饰不用文字填充；既有页面标题与输入提示不重复表达相同意思。
- 概念图中的示例视频也采用具体标题、说明与数据，避免无意义的鼓励语。
- 删除不提供额外信息的副标题、重复数量与常驻操作提示；错误原因、任务状态、输入标签和无障碍名称保留。

概念图只作为方向参考，不能逐像素继承其中的示例文字、虚构数据或自动生成的布局偏差。
落地时再缩小过大的页面标题、收紧工作台空隙；真实视频不被自动套上纸感或映芽宠物。

## 2. 九套风格如何收敛

**推荐采用一个固定的纸感界面，纸相关插画作为内部素材系列。** 不再进入新会话随机切换整套 UI。

| 原系列 | 后续用途 |
| --- | --- |
| `paper` 纸上放映室 | 主系列，覆盖六类页面场景 |
| `pencil` 铅笔动画工作室 | 分镜、构思、空状态等纸面线描插图 |
| `letterpress` 版画故事工坊 | 少量印章感图案、作品展示与页尾插画 |
| `watercolor` 水彩自然手记 | 有边界的纸面小画，用于外围页面局部 |
| `crayon` 蜡笔绘本 | 轻量涂画点缀，控制色彩与出现频率 |
| `screenprint` 丝网印刷 | 海报或印刷品形式的局部图案，挑选与主风格协调的素材 |
| `felt` / `wood` / `cel` | 完整保留作为后续创意资源，退出全局界面主题候选 |

资源保留：

- `web/src/assets/themes/` 的 54 张 WebP 全部保留。
- `output/theme-art/` 中的原稿、提示词、清单和来源记录全部保留。
- 素材“保留在仓库”与“首屏加载”分开；按页面加载实际使用的图片。
- 不把产品装饰直接混入用户的个人素材库，也不修改客户视频的画面风格。

工程上将 UI 主题与插画选择解耦：固定纸感 token，插画由页面角色、位置、尺寸和来源决定。
旧 `yingya-studio-theme-v1` 选择统一回落到纸感，保持草稿、附件、头像、任务和播放状态。
移除全局「换个画风」入口；首版使用固定策划的插画组合，后续如保留趣味切换，只切同页纸面插画。

## 3. 增加装饰的具体方法

使用三种尺度形成层次：一幅主题场景、两三处小纸物件、少量有意义的纸面图案。
每屏最多一个主插画焦点，物件集中在边角和页头，不铺在正文、列表和输入文字下面。

- **创作首页：** 主场景使用纸框与小鬼；输入区呈现干净纸笺；外围增加分镜纸条、纸夹或铅笔小画。
  输入框和发送按钮始终是首要操作，不为了装饰新增任务步骤或营销模块。
- **我的作品：** 页头采用小鬼整理画框的场景，局部像作品索引页；已有作品使用真实封面，空状态可展示更完整插画。
- **素材工坊：** 文件夹与纸片场景用于页头；类别图标和缩略图保持清楚，素材变多时自动让出装饰空间。
- **登录／注册：** 纸门迎接小鬼与清楚的表单构成主画面，桌面可偏置排版，手机改成简洁上下结构。
- **账户／账单：** 手账插画与小型页签增强纸面感，数字和表格保持紧凑、对齐。
- **工作台：** 仅保留小鬼品牌标识、纸色外框与极少量局部点缀；不新增大幅装饰页头。
- **官网：** 用更完整的纸面场景与真实产品内容形成节奏，每段保留呼吸空间。
- **分享／制作等待：** 小尺寸场景与清楚的状态说明；分享视频优先。

现有纸张插画的原稿是白底，并带局部接触阴影。不能直接贴到暖纸色大背景上造成白矩形。
首选以有意设计的浅色纸页承载原图；需要散落物件时制作新的透明衍生素材，保留原图与来源。
不使用全局混合模式处理图片，以免改变小鬼、插画颜色或用户媒体。

Kami 的墨蓝线描与书刊构图作为装饰语言参考；具体场景优先复用映芽原创资源。
不要把 Kami 示例中的其他产品标识、示例数据或文档截图当成映芽内容。

## 4. 页面密度分级

| 页面 | 密度 | 布局要求 |
| --- | --- | --- |
| 官网、登录、创作入口 | 低到中 | 集中主体、明显留白、完整场景与少量纸物件；不强行铺满 |
| 作品、素材工坊 | 中到高 | 紧凑筛选与列表；装饰主要在页头和空状态，数据增多时退后 |
| 账户、账单、管理 | 高 | 表格可扫读、操作稳定，页头装饰不占多余高度 |
| 正式制作工作台 | 高 | 保持左对话、右方案／视频、可调分栏和固定输入；常用操作直接可见 |

工作台继续采用现有桌面双栏：对话默认约三分之一，320–560px 可调，预览至少 480px。
小于 1024px 使用对话／方案／视频标签；不新增时间线编辑器或固定第三栏。
项目标题、状态、版本、停止、发送、分享和下载仍容易找到。技术日志继续按需展开。

同一视口和同一数据下，改造后的有效对话、方案和列表展示面积不得因装饰减少。
高密度靠分组与间距实现，不靠缩小字体和点击区域。

## 5. 实施顺序

### 第一批：统一底色与两个代表页面

先捕获当前页面作为对照；使用相同数据和视口验证前后密度。无法取得登录数据的页面用隔离 API mock。

| 工作项 | 具体改动 | 完成标准 |
| --- | --- | --- |
| 设计基线 | 暖纸色、墨蓝、标题字体、表面层次；整理插画清单并固定页面搭配 | 不再随机换整套画风；全部原素材留存 |
| 创作首页 | 保留短导航和中央输入；纸框小鬼主场景，配分镜纸条与局部小图案；输入区做轻纸层 | 首屏能看到并使用输入与发送；视觉有层次且不铺满 |
| 正式工作台 | 保持现有左右分栏；顶栏、对话、方案、视频、输入和状态统一纸感；紧凑操作使用原字号 | 同视口下有效内容面积不减少，常用动作不被新增折叠隐藏 |

首页桌面主体以现有输入区域为中心形成一组构图，主插画和边角装饰建立疏密；
手机只保留主插画及必要操作，去除次要纸物件。工作台不引入大标题、横幅或占位插画。

涉及文件：`web/src/styles.css`、`web/src/studioThemes.ts`、`web/src/components/StudioTheme.tsx`、
`web/src/studio-themes.css`、`web/src/App.tsx`、`web/src/home.css`、
`web/src/components/AgentWorkspace.tsx`、`web/src/knowledge-layout.css`。

### 第二批：作品和素材

- **作品页：** 紧凑标题、数量、搜索和筛选；纸框小鬼放在页头边侧；作品仍用真实封面和明确状态。
  无作品时使用完整场景，无搜索结果时用更小的提示，避免重复大型空状态插画。
- **素材工坊：** 页头纸文件夹插画；分类、搜索、上传、创建入口稳定排列；缩略图和详情仍是主体。
  抽屉、参考素材选择、音色与模型菜单一并统一，避免主页面完成后浮层仍是旧视觉。
- 两页都分别检查空白、少量、多量、加载、失败、长名称与窄屏状态。

涉及 `web/src/App.tsx`、`web/src/components/AssetStudio.tsx` 及其对应样式，
以及素材选择、音色、模型和通用弹窗组件。沿用已有数据与操作。

### 第三批：外围页面与细节收口

| 页面 | 具体交付 |
| --- | --- |
| 登录、注册、重置密码 | 纸门场景、紧凑表单、清楚的错误／禁用状态，桌面留白与手机单列 |
| 账户、用量、账单、管理 | 小手账页头、紧凑表格和一致表单；只调整展示，不改变金额、统计口径或权限 |
| 官网 | 保留小鬼品牌和现有内容结构，调整纸面构图、标题、按钮、插画及段落节奏 |
| 分享与制作等待 | 小型纸框场景、清晰状态与媒体区域，不改变分享逻辑或播放行为 |
| 全局组件 | 导航、账号菜单、按钮、标签、输入、焦点、提示、浮层统一 |

### 第四批：UI 验收与发布

完成前端类型检查、构建、相关单元测试与隔离数据下的浏览器回归。
按下方状态矩阵验收截图和交互，再建立不可变 release 并核对公网前端资源。
真实视频生成、模型效果、后台吞吐和真实计费不属于这一版验收。

避免只追加一层全局覆盖 CSS；按组件梳理旧冷灰值、旧主题材质规则和未使用的主题控制逻辑。
更新针对九主题随机的旧测试，使其验证固定纸感、旧存储兼容、插画按需加载和用户状态不丢失。

## 6. 验收与上线要求
