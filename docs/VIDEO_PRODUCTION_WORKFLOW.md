# 视频制作流程

当前产品以 [知识讲解制作约定](../skills/yingya-video-agent/references/knowledge-video.md)、[新版方案](YINGYA_NEXT_PRODUCT_DIRECTION.md) 和 [验收记录](YINGYA_KNOWLEDGE_ACCEPTANCE.md) 为准。目标是能独立讲清内容、可以分享的视频；不提供用户编辑器或视频生成模型/API。

1. **理解内容。** 从想法、文字和已有素材整理目标观众、核心问题、结论与事实依据。必要问题集中询问，建议 1–3 分钟中文讲解，用户可改。
2. **生成可预见的方案。** 保存结构化大纲与稳定段落 ID，说明每段讲什么、怎么表现。从实际制作源渲染开场、核心解释和结论三张画面，不足三段时按实际段数。这个有限的源制作与截图已属于方案阶段授权；不使用无关概念图。
3. **绑定方案确认。** 确认携带检查点、方案内容修订和去重请求 ID。修改方案使旧确认失效，未完成画面或更新中的方案不能确认。确认后的全片制作直接进行，内部代表片段检查不再要求用户审批。
4. **制作声音与动画。** 用六类内部表达组件、已适配组件和 GSAP 组织概念、流程、比较、数据、因果及素材标注。遵守项目统一的字体、颜色和动效规则。按实际旁白安排节奏与逐句字幕，校正转录中的同音字及数字。旁白服务失败保留成果并提供恢复，不能静默交付无声结果。
5. **检查实际作品。** 运行 HyperFrames 检查并审阅实际 MP4；验证事实、公式、数值、素材、字幕、声音及关键画面一致性。实际视频与冻结源、质量 JSON、审阅证据一起封存。渲染成功不等于讲解与审美通过。
6. **自然语言修改。** 截图、时间点或时间范围绑定原视频版本；通过稳定段落映射到当前版本。普通局部修改直接执行，保留其他内容和旧版本；段落时长变化同步后续声音、字幕与定位。每条意见必须关联真实新视频与可核查结果，无法完成的保留原因。
7. **分享或下载。** 用户可以直接分享所看版本的独立视频副本，或导出 MP4，不需要再次批准草稿。后续项目修改不改变旧链接。浏览器不要求自动有声播放。

历史工程与原方案文档仍可读、播放与导出。素材不足时说明缺口；不能自动重启关闭的视频生成任务。目标观众理解测试和真实设备测试单独记账，不以模拟界面通过代替真实成片验收。

## 长命令与自动接续

检查和渲染通过 `runtime/production-task.py` 运行，使用当前请求编号保存任务记录。
命令等待窗口结束时仍保持运行；完整工具结果保留 session ID 和退出码，丢失句柄时可查询任务编号。
报告只在进程成功、JSON 完整且输入未变时原子发布；stderr 独立保存，不能写入检查 JSON。
源文件、依赖、参数和产物摘要匹配时可复用结果，原任务的文件锁阻止重复启动。

模型回合结束后，后端先核对原检查/渲染任务。有新的成功结果且原请求授权完成制作时，
最多自动接续两轮，只补齐原任务内的步骤；接续次数和已消费结果持久保存。
检查或解释请求不启用制作接续，用户停止、等待输入、审核点、实际失败、执行结果未知及无新进展时停止。
服务滚动更新等待当前逻辑任务结束；异常重启后保持原有确认恢复机制，不自动重发不明确的外部请求。
这套机制不增加声画验收门槛，不以空白画面、静音或视觉启发式判定人声不同步。

验证入口：`npm run test:production`（真实子进程、文件锁与原子输出）和
`npm run test:rolling`（模拟模型提前结束、后台等待、接续、停止及版本切换）。
