# 用户沙箱与用量统计（内测版）

## 试用

打开映芽，在“邀请注册”中填写邀请码、邮箱和密码。注册后通过邮箱和密码登录。侧栏账号菜单提供用量统计，管理员另有“账号管理”入口。

密码使用 Argon2id 加盐哈希；会话与邀请码仅存哈希。当前不发送验证邮件，绑定邮箱的邀请应由管理员私下交给本人。旧的邮箱直接登录会话失效；旧账号需要绑定原邮箱的专属邀请设置密码，项目、素材和历史用量保留。通用邀请不能认领旧账号，也不能注册配置中的管理员邮箱。

在 `.env` 配置 `YINGYA_ADMIN_EMAILS=admin@yingya.local`，或用逗号分隔多个管理员邮箱。也可以在宿主终端创建带管理员身份的绑定邀请：

```bash
cargo run -- account-invite owner@example.com --admin
```

输出的一次性邀请码有效期 7 天，默认附带 1B（1,000,000,000）Token 和 40 次素材生成，后台新建用户、邀请码和终端新建管理员均使用这个默认值。普通绑定邀请去掉 `--admin`。这些命令不会启动服务或修改运行中任务的记账状态。不要将输出写入版本控制。

管理员在“账号管理”中创建邀请，可设受邀邮箱、1 至 365 天有效期、1 至 1,000 次兑换及每人初始额度。邀请码只显示一次，复制链接通过 URL fragment 携带凭据，打开后会从地址栏清除。追加额度使用请求编号去重，并记录操作者。

忘记密码时，管理员可为已激活账号创建一小时有效的一次性重置链接。宿主也可以执行 `cargo run -- account-reset owner@example.com`，使用输出的 code 构造 `/app#reset=CODE&email=EMAIL`。重置后旧会话全部失效；额度不变。管理员不会自动获得其他用户的项目访问权限。配置 HTTPS 部署时设置 `YINGYA_SECURE_COOKIES=true`。

## 管理后台

访问 `/admin`，使用管理员的邮箱和密码登录。普通用户仍在 `/app` 使用邮箱和密码。后台与工作台共用登录会话，但所有管理接口单独验证管理员权限。初始化独立管理员账号：

```bash
cargo run -- admin-create admin admin@yingya.local
```

命令生成随机密码，只能新建账号，不覆盖已有邮箱或密码。输出不得提交到版本控制；首次登录后可在后台修改密码。用户名为 3 至 32 位英文字母、数字、下划线、点或连字符，不区分大小写。用户名仅作为可选资料，不用于登录；通过邀请激活的管理员也直接使用邮箱登录。

- 用户管理：创建账号，编辑姓名、用户名、邮箱、备注和角色，调整 Token / 素材总额度，查看已用和剩余额度，搜索、状态筛选、分页、CSV 导出。
- 停用会撤销会话；归档同时停用账号，但保留项目、历史用量和用户 ID，可恢复。不能停用、归档或降级自己；配置中的管理员邮箱不能被改名或降级。修改邮箱、用户名、角色或状态时会撤销旧会话及未使用的密码重置链接。
- 邀请码：创建邀请，编辑名称、绑定邮箱、截止时间、可兑换次数、每人初始额度，停用/恢复，查看兑换用户。修改额度只影响之后的兑换，已兑换用户的额度需在用户管理中单独调整。邀请码明文不能再次查看。
- 密码和会话：生成用户的一次性密码重置链接、撤销用户全部登录会话、修改自己的密码。密码修改成功后需重新登录，不展示已有密码。
- 操作记录：查看最近 500 条管理操作，按操作类型筛选或搜索；不记录密码、邀请码或重置令牌明文。用户和邀请编辑带版本检查，过期页面保存时提示刷新，避免覆盖其他管理员的修改。

本版面向小规模内测，列表在浏览器筛选和分页。用户额度不能下调到已消耗与预留之和以下；不会清零历史账本。

用量与额度以 K / M / B 显示（千 / 百万 / 十亿），最多两位小数；编辑框、CSV 导出和后端账本仍保留精确整数。需要同步提高旧默认额度时，先备份数据库，再执行 `cargo run -- accounts-upgrade-defaults`：仅将 Token 总额度恰为 1,000,000 且素材总次数恰为 20 的账号和邀请码调整到 1B / 40，不改其他组合、不清零消耗与预留、不改变账号或邀请状态，并写入操作记录和编辑版本。此命令不会随服务启动自动执行。

## API 等价账单

创作模型只开放 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`。菜单、创作 API 和宿主中继都校验此范围；旧浏览器保存的其他模型会回到默认 Terra，打开旧项目不改写原项目记录，下一次提交使用当前选择。

用户从账号菜单打开“API 等价账单”，只能查看自己的账单。管理员从 `/admin/billing` 查看全部用户或筛选单个用户。账期为北京时间自然月，金额使用 USD；不扣款、不影响 Token 配额，也不是税务发票。

- 从宿主中继的终态响应读取输入、输出和缓存输入，不使用浏览器提交的 Token 或金额。缓存属于输入的子集，推理属于输出的子集，不重复相加。
- 输入金额 =（输入 - 缓存输入）× 普通输入单价 + 缓存输入 × 缓存单价；输出金额 = 输出 × 输出单价。单次输入超过 272K 时，输入及缓存按 2 倍、输出按 1.5 倍。
- 采用 Standard 文本 Token 参考价；不含缓存写入溢价、Fast / Batch 差价、素材与工具费。与供应商真实账单可能不同。
- 单价版本为 `openai-standard-2026-09-11`，在调用开始时保存，结算与配额账本处于同一个数据库事务。金额以整数纳美元累计，不按每次调用四舍五入到分。之后改价不会重算已有调用。
- 正在进行、用量不完整、模型名称不匹配以及缺少输入/输出明细的旧调用标记为待核对，不伪装成零费用。未发出或明确失败的调用按零结算；异常中断的配额预留规则不变，费用仍待核对。
- “生成账单”保存当前账期快照，包含编号、用户、模型、输入/缓存/输出数量、单价、分项金额与待核对次数。相同内容重复生成返回同一张账单；后续用量可生成新快照，旧账单不变。管理员为指定用户生成的账单该用户也可查看，全员汇总账单仅管理员可见。
- 账单支持 CSV 导出，保留精确 Token 和 9 位美元小数，不使用 K/M/B 缩写；界面仍使用紧凑数量格式。每月显示最近 100 份快照。

参考单价（USD / 1M Token）：

| 模型 | 输入 | 缓存输入 | 输出 |
| --- | ---: | ---: | ---: |
| [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) | 10 | 1 | 50 |
| [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) | 4 | 0.4 | 20 |
| [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) | 2 | 0.2 | 12 |
| [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) | 0.2 | 0.02 | 1.2 |

私有 API：`GET /api/billing?month=YYYY-MM`，`POST /api/billing/invoices`（JSON: `month`），`GET /api/billing/invoices/{id}`。管理员路径为 `/api/admin/billing`，查询及生成时可附 `userId`；普通接口不允许指定别人的用户 ID。

## 内测额度规则

- 额度按账号累计，不按月重置。Token 与素材次数独立管理，普通账号和管理员都受自己的额度约束。
- 新任务和每次宿主模型中继调用都检查额度。中继以事务预留最多 32,768 Token（余额不足则预留余额），并发调用不能重复使用已预留额度。供应商的实际总 Token 在响应结束时结算；缓存输入和推理输出不重复相加。
- 第一版是调用边界限制：已经发给供应商的单次请求可能超过预留或剩余额度。实际超额仍记账，之后的调用被拒绝；不是供应商级逐 Token 硬上限。
- 在发出请求前取消、明确的上游错误状态和连接建立失败不扣 Token；已发送但没有收到用量的调用暂按预留数扣除，标记为待核对，不当作零消耗。重启以事务结算未完成预留，重复恢复不重复扣除。
- 图片请求按模型声明的 `image_generation` 工具预留素材次数，余额耗尽时中继移除此工具。实际图片调用按响应输出项结算。语音创建、克隆、试听及 Agent 语音合成每次提交扣 1 次素材额度，包括失败尝试；普通音频文件播放、上传和音乐库搜索不计入。
- 用户“用量统计”显示总额、消耗、预留及剩余。额度耗尽仍可查看、下载作品；停用账号会撤销会话并阻止内部服务继续发起调用。
- 额度账本由宿主模型响应结算；原 Token 统计仍按 Agent turn 事件展示执行明细。两者可能因历史统计、待核对调用或压缩请求存在差异。旧账号激活时在原消耗之上发放邀请额度。

## 存储和会话

- SQLite：`data/yingya.sqlite`，保存用户、密码哈希、邀请、哈希后的会话令牌、请求和额度账本。不会挂载给 Agent。
- 用户内容：`data/users/<user-id>/projects`、`assets`、`voices`。
- 用户运行状态：`data/users/<user-id>/runtime`，包含独立 Codex home、工具 home 和封面缓存。
- Cookie：HttpOnly、SameSite=Strict，有效期 30 天；退出后服务端立即吊销。
- 浏览器草稿按用户划分 localStorage 与 IndexedDB；其他标签页收到账号切换通知后重新加载。
- 文件 URL 包含用户 ID，后端检查身份。不能通过复制其他账号的项目 ID、素材链接、事件流地址访问其内容。

现有 `data/video-projects`、`data/assets` 和共享 Codex 历史保留原样，不自动分配给第一个登录的人。已有共享项目需要在确认归属邮箱后另行迁移。新统计不回填无法完整归属的旧数据。

## 执行隔离

本版使用 Linux Bubblewrap（`bwrap`），不要求 Docker 守护进程。宿主机需允许非特权用户命名空间，并已安装 Node.js、Codex、HyperFrames 和浏览器依赖。

每个账号独立启动 Codex app-server。Agent 与渲染命令运行在私有文件系统、PID 和网络命名空间中：只挂载本用户的数据，可只读访问已安装的系统工具、项目依赖和浏览器。不会挂载整个仓库、其他用户目录、宿主 `.env` 或个人 Codex home。缺少隔离能力时运行环境启动失败，不降级为宿主直接执行。

共享平台模型凭据只保存在宿主侧 `YINGYA_CODEX_HOME/auth.json`（开发环境默认 `.runtime/codex-home/auth.json`），不复制到用户目录。用户 Codex home 只含不能直接访问供应商的占位登录信息；真实授权头由宿主模型中继注入。中继仅接受专属网关的内部身份，只允许指定的模型、Responses 和用量接口，禁止任意目标与重定向。启动后端时会替换旧版留在用户目录中的凭据副本。

当前 Codex 0.153.4 使用 Responses HTTP/SSE 中继，保留请求压缩和流式响应。宿主侧读取最新登录，提前刷新即将到期的 ChatGPT access token；登录被撤销时明确报错，需要在宿主重新登录。平台仍统一承担模型调用，用量按用户归属记录。此隔离面向 Agent 工作区，不防御能够直接读取宿主进程或文件的本机系统用户。

网络经过本用户专属 Unix socket 网关：普通出站只允许公共 HTTP/HTTPS，拒绝私网和宿主回环直连；语音和映芽内部请求由网关注入服务端用户身份。使用开发代理时，平台与内置 CDN 的可信域名保留域名路由，其他目的地固定到已校验的公网 IP。Chromium 也经过同一网关。代理环境只由宿主网关使用，不将宿主服务密钥传入 Agent 的环境变量。自定义后端端口需同步设置 `YINGYA_INTERNAL_API_BASE`。

VoxCPM2 只应监听 `127.0.0.1:8791`。自定义音色在服务端加用户命名空间，列表、预览和合成均限制归属。参考音频副本保存在各自的 `voices` 目录。

## 预览

多用户工作台展示当前 composition 的实时预览，自动适配画布大小，并支持播放和暂停。独立窗口入口为只读预览，不启动可公开直连的 HyperFrames Studio 编辑器端口。

预览 URL 带不可猜测的只读令牌，只能读取对应项目文件，30 分钟有效，工作台心跳续期。它与创建它的登录会话绑定，退出登录后失效。URL 属于访问凭据，不应分享。后端对 HTML 设置 CSP sandbox、禁止表单提交与 referrer，生成页面无法读取父页面、账号 Cookie 或工作台 API。普通下载与项目文件 API 仍检查登录和归属。

## 用量口径

- 请求次数：成功接收的创作/修改消息、素材工坊模型请求；创作队列使用已有请求 ID 去重。页面刷新、列表轮询不计入。
- 执行轮次：实际启动的 Agent turn。自动标题、重试也记到发起用户；不是不可见的供应商内部 HTTP 调用次数。
- Token：在 Codex 标准输出读取结构化事件时落 SQLite，不依赖浏览器连接或项目日志。
- 同一 thread 的累计计数取增量，重复事件不重复相加。失败、中断仍保留已收到的用量。未收到用量显示为未知执行，而非零消耗。
- 输入、输出、缓存输入、推理输出与总 token 分开显示；明细不重复加到供应商总数中。不是金额或账单估算。
- 模型筛选作用于执行与 token；请求次数仍显示该日期范围全部模型的请求数。
- 删除项目不删除用量。服务重启保留账号、会话与统计；未完成的执行标记为中断。

## 开发检查

用户运行环境按账号分别初始化，同一账号的并发请求共用初始化结果；失败或请求取消后撤销临时内部令牌，后续请求可以重试。任务完成和启动时的状态检查保留队列暂停，只有明确恢复或新提交才解除暂停。事件日志写入完成后才发布游标；实时事件缓冲区溢出会通知页面重新同步。项目文件按块传输，支持 Range、HEAD 和不可满足范围的 416 响应；路径检查针对访问的文件，不扫描整个用户目录。

```bash
npm run backend:service:restart   # yingya-backend，8797
npm run web:service:status        # yingya-frontend，8798
cargo test --all-targets -- --test-threads=1
npm run typecheck
npm run test:web
npm run web:build
YINGYA_UI_QA_URL=http://127.0.0.1:8797 npm run test:ui
cargo build
npm run test:admin              # 独立临时数据库，yingya-admin-qa，8800；结束时关闭
```

服务均通过命名 tmux 会话管理。浏览器检查可复用上述现有服务，不需要额外启动开发进程。
