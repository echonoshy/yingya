# 视频设计 Skill 接入方案

状态：第一阶段已发布；线上自动生成验收受上游模型故障阻塞。日期：2026-09-17。

已接入主 skill、规划与制作指引，新增按需读取的设计适配指南，收录 9 份固定
版本的上游参考和 2 份许可证。`npm run test:design` 校验来源哈希、文件清单与
引用闭包。没有新增 API、数据库字段或界面菜单；漫画和新可执行组件仍属后续阶段。

本次发布：`20260917-105920-design-references`，参考包 `1.0.1`。公开
`https://yingya.art/app` 的 JS/CSS 与发行版逐字节一致，测试租户的 17 个新增参考
及适配文件与发行版一致，测试 worker 已使用该版本。

已通过：skill 校验、参考完整性检查、租户递归复制测试、Rust 格式/lint、前端
类型检查/测试/构建、现有素材装配回归。另以人工编写的隔离样例验证了流程、
同尺度对比、竖屏分层三段 6 秒静音片：HyperFrames 检查与实际 MP4 导出通过，
每段 121 个 motion samples，倒退/重复定位图像一致，数据图形比例符合 40/70，
并查看了实际 MP4 抽帧。它们验证适配方法和运行时，不是网站模型生成质量的证据。

公开网站已通过 Playwright 登录并提交受控视频任务。新版任务在首次请求及一次
显式重试中均遭遇上游 `server_error` / stream disconnected；标题生成同样报错，
没有进入设计参考读取或成片制作。因此尚不能确认模型自动采用率、成片创意提升或
成本改善。旧版本对照在两次导出失败后通过应用中断接口结束，错误为占位时间轴
缺少真实 GSAP API；新版适配指南已补充可离线复用的实际脚本与许可证位置。
运行日志与隔离样例保存在本机 `/tmp/yingya-design-qa/`，不属于发行版资源。

## 建议

在现有 `yingya-video-agent` 内增加按需读取的设计参考与视频适配指引。
先接入信息图的结构选择、SVG 图解的方法，以及少量幻灯片构图参考，继续用
HyperFrames 和现有组件完成动画。目标是改善内容如何被看懂、镜头如何展开，
而不是仅增加配色或固定模板。

当前工作区正移除 `runtime/visual-styles` 和固定风格选择器。本方案以这一状态
为前提，不恢复旧目录或菜单。用户可以在对话中描述风格或提供参考，助手结合
内容推荐，并纳入现有制作方案；用户的品牌、素材和已批准设计优先。

## 已核实的接入位置

| 位置 | 当前能力 | 首版接法 |
| --- | --- | --- |
| `src/codex.rs` 的 `run_turn_once` | 视频任务显式附带 `yingya-video-agent` | 保持单一入口，由主 skill 引导按需读取 |
| `src/api.rs` 的 `install_bundled_video_agent_skill` | 递归复制主 skill 及其子目录到租户运行环境 | 将新参考放入主 skill 目录，无须新增全局安装器 |
| `src/sandbox.rs` | 挂载发行版的 skills/runtime，提供组件工具 | 复用现有资源访问方式 |
| `references/planning.md` | 方案包含视觉方向，`scenes.json` 保存文本分镜 | 增加内容结构、视觉隐喻、展开顺序和选择理由 |
| `references/production.md` | 批准后建立 `DESIGN.md`、制作场景并验收 | 把设计决定落实为可编辑元素及动画 |
| `runtime/components/catalog.json` | 标题、线性流程、数字对比、分支连线、模型展示 | 对匹配场景复用，其他场景按需编写 HTML/SVG |
| `scripts/release.py` | 快照包括完整 `skills` 和 `runtime` | 新参考跟随不可变发行版交付 |

仅安装到开发者自己的 skills 目录，不等于网站租户已获得能力。递归复制发生在
租户初始化时，发布后还需要验证实际承接新任务的 worker 和租户文件版本；已有
运行任务按现有机制排空，不强制中止。

## 首版建议改动

以下目录已实现：

```text
skills/yingya-video-agent/
  SKILL.md                              # 增加简短路由说明
  references/
    planning.md                         # 何时选结构、如何写进方案
    production.md                       # 设计如何落实为动态场景
    visual-direction.md                 # 选择与适配的总指南
    design/
      index.md                          # 用途、适用条件及参考路径
      information-structures.md         # 流程、对比、层级、拆解
      diagram-to-motion.md              # SVG 分组与语义动画
      slide-to-scene.md                 # 阅读页面到时间序列的转换
      references/                       # 固定版本的必要参考文件
      PROVENANCE.json                   # 来源 commit、文件、许可证、修改
```

主 skill 只增加入口说明，不把所有参考全文加入每次任务。助手先判断内容结构，
有需要再读取相关参考；已有项目的局部修改保留原设计，避免每次重新选风格。
如果第一阶段不新增可执行组件，预计无需修改 Rust API、数据库或前端。

首轮集中验证三类用途：知识流程、前后对比、系统拆解。它们是验收样例范围，
不是用户创作的白名单。现有 `flow-path` 仅适合少量线性阶段，`beam-network`
适合分支或汇聚，`number-compare` 适合有来源的指标。复杂结构仍需定制布局，
不能把任何信息都硬套成几张卡片。

## 设计决定如何进入成片

1. 规划时读实际资料，识别要解释的是顺序、关系、差异还是故事；选择合适结构，
   再确定全片视觉方向。风格参考不能改写事实、替换真实录屏或虚构数据。
2. 在 `.yingya/plan.md` 的视觉方向与制作方式中写明选择理由，并在 `scenes.json`
   中写清画面组织、旁白推进、动作和停留。无需新增第二套分镜文件。
3. 按现有方案确认流程进入制作。确认前允许文本构思与参考资料读取；新生成的
   风格帧、分镜图及视频属于批准后的制作，不增加另一轮风格确认。
4. 批准后将共同字体、色彩、线条、材质、动效节奏、字幕安全区和参考版本写入
   `DESIGN.md`。只在复杂设计需要时制作代表性场景，内部检查后再扩展。
5. HTML/SVG 保留文本、数字、节点、连线等独立元素。插画和纹理在适合时使用
   位图；数据含义和主要文字不能依赖不可编辑的整页图片。
6. 使用已测量音频或真实素材时间决定动画时点。GSAP 主时间线控制场景，组件
   使用现有时钟协议；支持直接定位、倒退及重复定位，不能靠翻页事件、页面加载
   时间或独立计时器启动动画。
7. 将使用的源码、素材、字体、参考版本和来源记录保留在项目及其版本快照中，
   避免历史作品依赖将来变化的参考资料。

场景字段可以先复用现有结构。例如下面是**规划示例，时间尚未测量，也不是
可直接运行的组件配置**：

```json
[
  {
    "id": "process-overview",
    "order": 1,
    "narrativeRole": "解释三个阶段如何连接",
    "narration": "先收集资料，再整理重点，最后生成结果。",
    "onScreenText": "从资料到结果",
    "visualDirection": "三个阶段沿同一条路径展开；沿用全片字体与色彩，当前阶段清晰突出",
    "assetIds": [],
    "assetStrategy": "可编辑文字与 SVG 节点；评估现有 flow-path 的适用性",
    "startSeconds": 0,
    "durationSeconds": 8,
    "timingBasis": "estimate",
    "motion": "旁白提到哪个阶段，就显示该节点并延伸连接；最后保留完整关系供阅读",
    "captionMode": "sentence",
    "transition": "cut",
    "status": "draft"
  }
]
```

`MediaScene.extra` 和前端 scene schema 支持保留额外字段，但这不代表字段已经
有执行语义。首版优先复用上述已有字段；未来若需要结构化自动装配，再增加有
schema、校验器和实际消费者的字段。不要复用录屏装配器的 `recipe` 来填风格名，
该字段已有具体含义。

## 验收与分阶段发布

第一阶段完成参考资料与主工作流适配，并制作三组短片：中文知识流程、带来源
的指标对比、保留真实素材的产品讲解。覆盖横屏和竖屏。对同一份素材、旁白、
模型及输出条件保留接入前基线，比较具体差异：是否看懂关系、文字是否可读、
镜头是否随内容推进、局部修改成本、生成耗时及调用成本。成本数据只报告实际
能记录的指标，不凭感觉给美学打分，也不预先承诺“必然更有创意”。

必要检查：

- 参考索引及相对链接完整，所选来源版本可追溯；租户隔离环境确实可读。
- 只修改一个节点文字、一个数字或一句旁白时，其余已批准设计可保留。
- 中文和字幕无溢出；信息密集页面按叙述拆成阶段，而非一次塞满画面。
- 同一时刻的直接、倒退和重复定位结果一致，动画与实际声音同步。
- 现有 HyperFrames check、render 通过；打开实际 MP4 抽帧并听音确认效果。
- 旧项目、真实录屏与用户指定风格不被新参考覆盖。

第二阶段只将验证中反复出现、适合参数化的场景沉淀进现有组件目录，并增加对应
运行检查。第三阶段再扩展漫画、拼贴等依赖图像资产的表达。第一阶段的接入不
应等待所有风格或组件全部做完。

实际产品改动按仓库要求创建并激活新发行版，检查公开页面资源、实际 worker
版本和网站中的受控生成任务；运行中任务正常排空。仅主 skill 文档变化也会
改变产品生成行为，实施阶段需要发布验证。本文件本身仅为方案文档，不触发部署。
